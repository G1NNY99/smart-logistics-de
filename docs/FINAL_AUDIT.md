Эти результаты получены из пользовательских логов. **Повторный старт с нуля пока не подтвержден**: для этого предназначен `tests/verify_cleanroom.ps1`.

## Clean-room проверка без риска для рабочей базы

1. В корне проекта с настроенным `.env` выполните:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\verify_cleanroom.ps1
   ```

2. Скрипт создает временную копию исходного проекта, подключает существующий `.env` как входные переменные Compose (не копируя пароль и не выводя его), удаляет в копии только публикацию порта PostgreSQL `55432`, задает **отдельное имя Compose-проекта** и запускает *новую* базу с *новым* томом. Рабочие контейнеры и файлы остаются нетронутыми.
3. Затем проверяет, что с нуля получены исходные 300 000 строк, корректные Core/Quarantine/Mart/ML, результаты SQL-assertions, отсутствие future labels и файлы модели.
4. При успехе выводит `[PASS] CLEANROOM ...` и название временного Compose-проекта. **Автоматического удаления тестовых ресурсов нет.** Согласуйте очистку после проверки.

## Перед GitHub

- Убедиться, что корневой README объясняет запуск, архитектуру, SQL и результаты.
- Запустить `tests/verify_repository.ps1`; убедиться, что `.env`, персональные реестры и `artifacts/` не входят в `git ls-files`.
- Убедиться, что `.dockerignore` исключает `.env` из контекста сборки Docker.
- Проверить репозиторий после `git add`, затем создать коммит и опубликовать по явному подтверждению владельца.

## Ограничения и открытые риски

1. Требование «`docker-compose up` одной командой на чистом ПК» нуждается в однократном создании `.env` из `.env.example` для установки пароля. Рабочая Compose-команда после настройки запускает всю цепочку.
2. Винтаж фиксирован: `as_of=2026-10-26`; это не актуальный поток производственных данных.
3. Это тест на синтетических данных: бизнес-метрики и ML-качество не переносимы напрямую на production.
4. Наличие зеленых SQL-assertions доказывает только проверенные инварианты; требуется отдельная проверка clean-room перед утверждением о воспроизводимом развертывании.
